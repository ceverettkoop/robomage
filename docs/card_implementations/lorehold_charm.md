# Lorehold Charm

## Oracle text

> Lorehold Charm {R}{W}
> Instant
> Choose one —
> • Each opponent sacrifices a nontoken artifact of their choice.
> • Return target artifact or creature card with mana value 2 or less from your graveyard to the battlefield.
> • Creatures you control get +1/+1 and gain trample until end of turn.

## Script source + key tags

`bin/resources/cardsfolder/l/lorehold_charm.txt`:

```
Name:Lorehold Charm
ManaCost:R W
Types:Instant
A:SP$ Charm | Choices$ DBSacrifice,DBChangeZone,DBPumpAll
SVar:DBSacrifice:DB$ Sacrifice | Defined$ Player.Opponent | SacValid$ Artifact.!token | ...
SVar:DBChangeZone:DB$ ChangeZone | Origin$ Graveyard | Destination$ Battlefield | ValidTgts$ Artifact.cmcLE2+YouOwn,Creature.cmcLE2+YouOwn | ...
SVar:DBPumpAll:DB$ PumpAll | ValidCards$ Creature.YouCtrl | NumAtt$ +1 | NumDef$ +1 | KW$ Trample | ...
```

Key tags exercised:
- `SP$ Charm` modal spell — `Choices$` lists the three sub-ability SVars (CR 700.2 / 601.2b modal).
- `DB$ Sacrifice | Defined$ Player.Opponent | SacValid$ Artifact.!token` — each opponent sacrifices a nontoken artifact.
- `DB$ ChangeZone | Origin$ Graveyard | Destination$ Battlefield | ValidTgts$ ...cmcLE2+YouOwn` — targeted reanimation.
- `DB$ PumpAll | ValidCards$ Creature.YouCtrl | NumAtt$ +1 | NumDef$ +1 | KW$ Trample` — mass until-end-of-turn pump.

## Engine work done

1. **New general `PumpAll` effect handler** (the only missing mechanic, per triage).
   - `EffectKind::PumpAll` added to the enum (`src/effects/effect_kind.h`) and the
     string table (`src/effects/effect_kind.cpp`).
   - `src/effects/effect_pump_all.cpp` (new): iterates battlefield creatures matching the
     `ValidCards$` filter via the shared `permanent_matches_filter` (so `YouCtrl`/`OppCtrl`
     scoping and the full qualifier grammar come for free) and applies the same
     until-end-of-turn +P/+T and granted keyword(s) that single-target Pump applies.
   - Registered the dispatch case in `src/effects/effect_table.cpp`. No new parse hook is
     needed: `ValidCards$` is consumed by the existing `parse_destroy_all` (shared
     `Ability::valid_cards_filter`) and `NumAtt$/NumDef$/KW$` by the existing `parse_pump`.
   - **Reuse, not duplication:** the per-creature application logic was factored out of
     `effects::pump` into two shared helpers in `src/effects/effect_pump.cpp`:
     `apply_pump_to_creature(target, att, def, pp)` (the EOT-bucket +P/+T + keyword grant +
     logging, CR 514.2/611.2b cleanup path) and `resolve_pump_amounts(...)` (static literal
     vs. count-SVar magnitude resolution). Single-target `pump` and mass `pump_all` now share
     both, so the cleanup mechanism / timestamp / keyword de-dup is identical.

2. **Targeted graveyard→battlefield reanimation targeting** (a second gap surfaced while
   testing the reanimation mode). The targeting-legality predicate and the candidate
   enumerator both special-cased graveyard ChangeZone targets with
   `destination != BATTLEFIELD`, so a reanimation mode (`Origin$ Graveyard | Destination$
   Battlefield`) was never offered.
   - `src/components/ability.cpp` (`is_legal_target`): the graveyard-target branch now
     matches a graveyard-origin ChangeZone target regardless of destination, and additionally
     enforces the `cmcLE` mana-value bound (read from the card's printed mana value, since a
     graveyard card has no live MV layer) — needed for `cmcLE2`.
   - `src/action_processor.cpp` (`build_valid_targets`): the candidate enumerator drops the
     same `destination != BATTLEFIELD` restriction so it scans the graveyard for reanimation
     targets.
   - `src/effects/effect_change_zone.cpp` (targeted move branch): a target reanimated from a
     non-battlefield origin to the battlefield now enters under the ability's controller
     (`ab.controller`) and honours `enters_tapped`/`enters_transformed`, matching the
     search/defined paths. Guarded with `ab.origin != Zone::BATTLEFIELD` so existing
     battlefield→exile/graveyard targeted moves (Swords to Plowshares, etc.) are unaffected.

3. Registered the card in `src/card_vocab.h` as `{"Lorehold Charm", 198}` (highest prior index
   197; `N_CARD_TYPES` = 1024 unchanged). `train/card_costs.py` regenerated by the build's
   pygen step.

## CR rule references

- CR 700.2 / 601.2b — modal spell "choose one"; modes must be different (handled by
  `effects::charm`, which also skips modes with no legal target).
- CR 611.2b / 514.2 — "until end of turn" continuous effects end during the cleanup step; the
  EOT bonus bucket (`Creature::eot_power_bonus` / `eot_toughness_bonus` / `eot_keywords`) is
  reverted there.
- CR 608.2 — a permanent put onto the battlefield by a spell's effect enters under the
  controller of that spell.
- CR 109/110/115 — characteristic / target matching, via the shared filter evaluator.

## Behavioral decisions

- PumpAll is implemented as a **general** mass-pump: any `DB$/AB$ PumpAll` with `ValidCards$` +
  `NumAtt$/NumDef$/KW$` now works (not special-cased to Lorehold Charm). A count-SVar
  `NumAtt$/NumDef$` is resolved per-matched-creature via the shared `resolve_pump_amounts`.
- As with every Charm card in this engine, modes are chosen at resolution rather than on cast
  (the documented engine-wide simplification).
- The reanimated permanent enters under the caster's control (the spell's controller returning
  it from their own graveyard).

## Tests run → results

Test harness (`train/test_harness.py`, torch-free), seed 1:

- **PumpAll mode** — battlefield-a `Voice of Victory, Ocelot Pride`; cast Lorehold Charm →
  "Creatures you control get +1/+1 and gain trample". Result: both creatures `1/3→2/4` and
  `1/1→2/2`, both gained Trample; by the opponent's turn (post-cleanup) both reverted to
  `1/3` and `1/1`. PASS (mass pump applied + wears off end of turn).
- **Reanimation mode** — graveyard-a `Ocelot Pride`; cast → "Return target ... mana value 2 or
  less". Result: the mode was offered (previously suppressed), `Ocelot Pride` moved from the
  graveyard to the battlefield under the caster's control and was able to attack and fire its
  own trigger. PASS.
- **Sacrifice mode** — battlefield-b `Mox Opal`; cast → "Each opponent sacrifices a nontoken
  artifact". Result: "Player B sacrifices Mox Opal"; Mox Opal moved to B's graveyard. PASS.

Scripted regression (torch-free), Boros aggro–style deck containing 4× Lorehold Charm vs. a
burn/creature deck, seeds 1/2/3, full games to completion: all decisive (Player A wins by life
loss, no draws), no non-fatal errors, no assertions. Lorehold Charm was cast by the scripted
agent in the seed-1 and seed-3 games.

Build: `make HEADLESS=TRUE` compiles clean (only pre-existing cosmetic "Unrecognized ability
param" warnings).

## Final result
