# Canoptek Scarab Swarm

```
Name:Canoptek Scarab Swarm
ManaCost:4
Types:Artifact Creature Insect
PT:1/1
K:Flying
T:Mode$ ChangesZone | Origin$ Any | Destination$ Battlefield | ValidCard$ Card.Self | Execute$ TrigExile | TriggerDescription$ Feeder Mandibles — When CARDNAME enters, exile target player's graveyard. For each artifact or land card exiled this way, create a 1/1 colorless Insect artifact creature token with flying.
SVar:TrigExile:DB$ ChangeZoneAll | ValidTgts$ Player | Origin$ Graveyard | Destination$ Exile | ChangeType$ Card | SubAbility$ DBToken | RememberChanged$ True
SVar:DBToken:DB$ Token | TokenAmount$ X | TokenScript$ c_1_1_a_insect_flying | TokenOwner$ You | SubAbility$ DBCleanup
SVar:DBCleanup:DB$ Cleanup | ClearRemembered$ True
SVar:X:Remembered$Valid Land,Artifact
```

**Oracle behavior:** 4-mana 1/1 flying Artifact Creature — Insect. ETB trigger ("Feeder
Mandibles") targets a player, exiles that player's entire graveyard, then for each **artifact or
land** card exiled this way creates a 1/1 colorless Insect artifact creature token with flying
under the controller's control.

## What already existed

- `T:Mode$ ChangesZone` self-ETB trigger.
- `DB$ ChangeZoneAll` with `ValidTgts$ Player` (operate on the targeted player's graveyard) —
  `src/effects/effect_change_zone_all.cpp`.
- `DB$ Token` (`src/effects/effect_token.cpp`), including dynamic `TokenAmount$` via
  `dynamic_amount_expr`.
- `DB$ Cleanup | ClearRemembered$ True` (clears `cur_game.remembered_entities`).
- `RememberChanged$` parsing into `ab.remember_changed`.
- The shared filter matcher `card_matches_filter` (`src/game_queries.h`), which matches a card's
  printed characteristics ("Land", "Artifact", etc.) from `CardData`/`Zone`.
- The token script `bin/resources/tokenscripts/c_1_1_a_insect_flying.txt`.

## Two reusable pieces added

1. **`ChangeZoneAll` now honors `RememberChanged$`.**
   `src/effects/effect_change_zone_all.cpp` — in the move loop, each successfully-moved entity is
   pushed onto `cur_game.remembered_entities` when `ab.remember_changed` is set, exactly mirroring
   the single-target `change_zone` path (`effect_change_zone.cpp`). Lifetime is identical: the set
   is cleared by the paired `DBCleanup` `ClearRemembered$` chain. This works for **any**
   `ChangeZoneAll`, not just this card.

2. **`Remembered$Valid <comma-OR-filter>` dynamic-amount handler.**
   `src/components/ability.cpp`, in `evaluate_dynamic_amount` — parses the comma-separated OR
   filter list after `Remembered$Valid ` and returns the count of `cur_game.remembered_entities`
   matching **any** listed filter, via the shared `card_matches_filter` (game_queries). The
   remembered cards are now in their destination zone (exile), so they are matched by printed
   characteristics. `"Land,Artifact"` = land OR artifact. General — usable by any SVar of this
   form.

   Supporting parse change: `src/parse.cpp` — the sub-ability `amount_svar` resolver now preserves
   a `Remembered$...` SVar expression into `dynamic_amount_expr` (previously only `Count$Valid` /
   `Targeted$` / `xPaid` / a couple of `Count$` forms were preserved), so `TokenAmount$ X` with
   `X:Remembered$Valid Land,Artifact` reaches the evaluator instead of falling through to 0.

## Test evidence (test harness, `--play` isolation, seed 1)

Cast from hand A with 4 Islands on the battlefield, targeting opponent B:

- Graveyard B = `Mountain, Lotus Petal, Lightning Bolt` → all 3 exiled, **2** Insect tokens
  created (Mountain=land, Lotus Petal=artifact; Lightning Bolt=instant, not counted). Tokens enter
  under A's control.
- Graveyard B = `Lightning Bolt, Lightning Bolt` → both exiled, **0** tokens created (no
  "Token created" line).
- Graveyard B = `Mountain, Island, Lotus Petal, Mishras Bauble` → all 4 exiled, **4** tokens.

No non-fatal errors, no draws in the `--play` lines.
