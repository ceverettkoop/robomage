# Recruiter of the Guard (vocab index 157)

## Oracle text
When Recruiter of the Guard enters, you may search your library for a creature card
with toughness 2 or less, reveal it, put it into your hand, then shuffle.

(2/W, 1/1 Creature — Human Soldier)

## Forge script
Source: pre-existing local (`bin/resources/cardsfolder/r/recruiter_of_the_guard.txt`).

Key tags:
- `T:Mode$ ChangesZone | Origin$ Any | Destination$ Battlefield | ValidCard$ Card.Self |
  OptionalDecider$ You | Execute$ TrigChange` — ETB trigger; the controller *may* perform the search.
- `SVar:TrigChange:DB$ ChangeZone | Origin$ Library | Destination$ Hand |
  ChangeType$ Creature.toughnessLE2 | ChangeNum$ 1` — search the library for one creature
  card with toughness 2 or less, reveal it, put it into hand. (Library origin implies the
  shuffle at the end.)

## Engine work
The ETB trigger, the optional-decider gate, the library `ChangeZone` search, the reveal, and
the shuffle were all already handled. The only gap was the search filter qualifier
`toughnessLE2`: the `ChangeType$` filter matcher treated any unrecognized `.`-qualifier as a
subtype name, so `Creature.toughnessLE2` looked for a creature with subtype "toughnessLE2",
matched nothing, and the tutor always failed to find.

Added a **general power/toughness comparison qualifier** to the search-filter matcher in
`matches_filter_spec()` in `src/components/ability.cpp` (the same function that already handled
the `cmcEQ`/`cmcLE` dynamic mana-value qualifier and the `Basic`/`nonBasic`/color qualifiers).
A new `try_pt_qualifier` lambda recognizes a qualifier of the form `power`/`toughness` followed
by a two-letter comparator (`LE`/`GE`/`EQ`/`LT`/`GT`/`NE`) and an integer, e.g. `toughnessLE2`
or `powerGE5`. It compares the card's base `CardData::power` / `CardData::toughness` against the
number via the shared `apply_svar_op()` operator table (`src/svar_eval.cpp`). It is fully
general over comparator, value, and which of power/toughness is referenced — not hardcoded to
this card or to the value 2. A qualifier that is not a P/T comparison is left untouched so the
existing color / supertype / subtype branches still apply.

Because `Creature.toughnessLE2` contains a `.`, the search already routed through the
"extended" filter path (`search_zone` in the same file), so no change was needed there.

Files changed:
- `src/components/ability.cpp` — `matches_filter_spec()`: added `try_pt_qualifier` and wired it
  into the dot-qualifier dispatch.
- `src/card_vocab.h` — registered `{"Recruiter of the Guard", 157}`.
- `train/card_costs.py` — regenerated by the build (`pygen`) for the new vocab entry.

## Behavioral decisions
- Comparison is against the creature card's *base* printed P/T while it is in the library
  (CR 208.2 — a card not on the battlefield uses its printed values; CR 107.1 for the
  numeric comparison). A static-text "*" P/T card (e.g. Barrowgoyf) reports its base 0/printed
  toughness; no continuous effect applies off the battlefield. No other ambiguity — the
  qualifier and the rest of the script are standard.

## Tests
All via `train/test_harness.py` (scripted full games can't use `train.py observe` here because
`torch` is unavailable in this environment; scripted-vs-scripted games through the harness
exercise the same engine).

1. **Filter includes only matching creature.** Recruiter cast with a library holding Solitude
   (3/2, toughness 2 → matches `toughnessLE2`) and Endurance (3/4, toughness 4 → no match).
   ETB search menu offered exactly `Fail to find` and `Solitude`; Endurance was excluded.
   Chose Solitude → "reveals Solitude and puts it to hand". PASS.
2. **No false match.** Recruiter cast with a library holding only Endurance (toughness 4).
   ETB search menu offered only `Fail to find` (no creature option). PASS.
3. **Real-game regression.** mav (G/W Knight) deck with 3 Recruiter of the Guard vs delver,
   scripted both sides, seeds 1–4, max 6000 decisions. All four games ended decisively by
   life loss (A wins seeds 1,2; B wins seeds 3,4) with no draws, no non-fatal errors, no
   asserts/segfaults (only the pre-existing cosmetic "Unrecognized ability param" warnings).
   Recruiter cast and its ETB resolved in real games. PASS.

## Result
Implemented. General `power`/`toughness` `LE/GE/EQ/LT/GT/NE` search-filter qualifier added;
Recruiter of the Guard searches for and finds only creatures with toughness 2 or less.
